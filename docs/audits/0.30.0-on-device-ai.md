# Audit: on-device AI for Ask Cochilo (0.30.0)

Date: 2026-11-03 · Auditor: Claude (impeccable critique, native; graphic-design-fundamentals §13)

## Scope

The owner's decision: Play delivery (play) and file import (github). `ai/` (runtime, state,
file checks, one source per build), `domain/assistant/Grounding.kt`, the Settings row and
`ModelSheet`, the model's answer and "thinking" cards in Ask, the `:assistant_model` asset pack,
the Release step. Design system 0.23.1.

Screens looked at: `model_sheet_play_light`, `model_sheet_import_copying_light`,
`model_sheet_ready_ptBR_dark`, `ask_generated_light`.

## Found while building (fixed before release)

| # | Severity | Issue | Fix |
|---|---|---|---|
| 1 | Critical | LiteRT-LM's Android library needs Kotlin 2.2+ (this project: 2.0) | MediaPipe's runtime behind `LocalModel`; LiteRT-LM after a Kotlin upgrade (roadmap) |
| 2 | Critical | Play Asset Delivery brought five permissions; the permission check failed the build | Each one reviewed and listed for play only, with why, in build.gradle.kts, distribution.md and AGENTS.md; no INTERNET; github unchanged |
| 3 | Important | "It can be wrong" tripped the never-judge test | "It can make mistakes" (the test stays strict) |
| 4 | Polish | Close sat tight under the progress line | space4 after progress and after "Not in this build" |

## Not verified here (needs a phone)

The model's speed, memory and battery on a real 4 GB Android; the Play pack download (needs the
app on a Play track and the `ASSISTANT_MODEL_URL` secret). The grounding check and file checks are
unit-tested; the runtime call isn't (it needs the native library).
