# 0.57.0: the model download carries on (four-skill audit)

The owner: "The download of the AI model is very large. It should be able to resume the download
in case of interrupted." What changed: the model comes in 100 MB pieces, finished pieces are kept,
and an interrupted download offers **Carry on downloading** from where it stopped
([assistant.md](../assistant.md), [flows.md](../flows.md)).

**How each skill was used.** All four were loaded with the Skill tool in this session before their
sections were written: `ux-user-flows`, `less-is-more`, `impeccable` (Cochilo's copy; its context
launcher ran and reported no PRODUCT.md, so the scoped fix used the code as context; its
`audit.native.md`, `android.md`, `craft-floor.md` and the start of `critique.md` were read; on a
native platform the critique runs Assessment A alone, so no detector) and
`graphic-design-fundamentals`. No emulator here: the screens were judged from Paparazzi
(`model_sheet_stopped_light`, `model_sheet_stopped_ptBR`), and the riskiest assumption has a
device test (testing-on-device.md §8, not yet run).

## 1. ux-user-flows

**Job story.** When the model's download stops halfway (the Wi-Fi drops for good, the phone
restarts, she removes it from Downloads), I want to carry on from where it was, so I don't spend
another hour and another 3 GB.

The flow, its states and taps are in flows.md ("The model download carries on"). §13 checklist:

| # | Check | Result |
|---|---|---|
| 1 | Job | ✅ one actor (a parent getting the model), one job, success = model Ready without re-downloading what arrived |
| 2 | Entries | ✅ Settings row, Ask's row under a reply, returning after a restart (the state is read from what's on disk at start) |
| 3 | Happy path | ✅ unchanged: Download, then nothing |
| 4 | Branches | ✅ dropped connection (resumes in the piece), stops for good (Stopped at N%), damaged piece, no space, Stop and delete, choose a file, whole-file check fails |
| 5 | States | ✅ downloading with progress over all pieces, waiting for Wi-Fi, stopped, damaged, no space, ready |
| 6 | Errors | ✅ plain words, the progress is kept (the "input" here), recovery is the primary button |
| 7 | Control | ✅ Carry on, Choose a file, Close; Stop now says it deletes |
| 8 | Progress and resume | ✅ the point of the change: Zeigarnik, the stopped state says how far and offers to finish |
| 9 | Memory | ✅ nothing to remember: the sheet says the percentage |
| 10 | Exits | ✅ Ready, or back to the sheet; no dead end |
| 11 | Conventions | ✅ the download manager's own notification and pause/resume; "carry on" like a browser's resume |
| 12 | Speed | ✅ progress line and percent; the long wait stays in the background with the notification |
| 13 | Accessibility | ✅ the stopped line is a polite live region; buttons are full width, 52dp |
| 14 | Ethics | ✅ the size is still stated before the first tap; Stop says it deletes |
| 15 | Evidence | ✅ the riskiest assumption (download-manager behaviour across makers, restart mid-piece) is device test 8 |

Heuristics: #1 visibility of status (stopped at N%) and #3 user control (carry on) were the gaps;
both fixed. **Finding (severity 2, fixed):** "Stop the download" read like a pause, but it deletes
what arrived; now "Stop and delete the download" (heuristic #2 match, #5 error prevention).

## 2. impeccable

Native Android, Operate mode. Critique (Assessment A): the stopped state is the existing sheet
with one sentence changed and one button label changed. Specific to the product (it speaks of
what arrived, not "error"), reassuring at the moment that matters (peak-end: the worst moment of
the download now ends in "carries on from there").

Audit (native, against android.md):

| # | Dimension | Score | Key finding |
|---|---|---|---|
| 1 | Accessibility | 4 | Live region on the stopped line; 52dp buttons; sp type; contrast unchanged (ink on page) |
| 2 | Performance | 4 | Pieces are hashed on the IO dispatcher as each lands; joining streams 1 MB at a time |
| 3 | Appearance & theming | 4 | Tokens only; no new colour |
| 4 | Platform conformance | 4 | Android's download manager and its notification; Back closes the sheet |
| 5 | Adaptivity | 4 | Same sheet; the Portuguese copy wraps cleanly (Paparazzi pt-BR) |
| **Total** | | **20/20** | Excellent |

Findings: P2 "Stop" ambiguity (fixed, above). No P0 or P1.
