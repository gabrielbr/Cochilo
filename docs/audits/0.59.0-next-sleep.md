# 0.59.0: the next sleep first, the day planned (four-skill audit)

The owner said three things:
- The next projected sleep "has a very similar color to what was already slept. This is the main
  information … it needs to be more primary."
- His suggestion: it "should be blinking in a softer way, like breathing, and with a more
  prominent color, maybe the Tatá Slings main color."
- He wants every projected sleep through the day "with time easily readable … so the user can
  plan ahead their day".

**How each skill was used.** All four were loaded with the Skill tool earlier in this session
(this conversation): `ux-user-flows`, `less-is-more`, `impeccable` (with `audit.native.md`,
`android.md`, `craft-floor.md` and `critique.md` read) and `graphic-design-fundamentals`. Their
checklists were applied again to this change's screenshots: `day_today_expected_light`,
`day_morning_projection_light` (new), `day_expected_block_ptBR_dark` and `day_pressure_light`.
There is no emulator here, so the breathing was checked in code rather than seen: it is still in
screenshots and with Remove animations.

**A rule changed, by the owner's decision.** "Teal is the one action, nothing else" now has one
exception: the next expected sleep. It is recorded in AGENTS.md and components.md. Teal stays a
fill there, never text. The time beside it is ink, in the label role.

## 1. ux-user-flows

**Job story.** When I open the Day tab between naps, I want to see at once when the next sleep
is and how the rest of the day looks, so I can plan a walk, a bath or a visit.

§13:
- **Job, entries, happy path:** ✅ no tap; the ring answers it.
- **States:** ✅
  - morning: several projected sleeps and bedtime;
  - afternoon: one nap left, then bed;
  - napping: the next expected sleep is bedtime;
  - past its window: the hour-by-hour list says so, as before;
  - no plan yet: nothing projected.
- **Memory:** ✅ nothing to remember; the times are on the ring and in the line under it.
- **Conventions:** ✅ "~" for an estimate, as the hour-by-hour list already does.
- **Evidence:** ✅ the times come from DayPlan, which is tested. Whether the breathing feels calm
  and not alarming is for the device: see testing-on-device.md, test 7 (TalkBack and screens).

Heuristic #1 (visibility of system status): the gap the owner found is now fixed.

## 2. impeccable

Native Android, Operate mode.
- **Critique:** the next sleep is now the first read, through colour, motion and weight. It's a
  single motion on the screen, slow (2.4 s each way, system easing), never a flash. The later
  sleeps stay quiet (dashed outlines) but readable (their times).
- **Peak-end:** the question she opens the tab with is answered first.
