# Audit: the next sleep on the timeline (0.50.0)

Date: 2026-11-04 · Auditor: Claude (impeccable, native; graphic-design-fundamentals §13;
less-is-more)

## Scope

The owner approved the 0.50.0 plan, "Go":
- one block, the next sleep only;
- no "Start now" on it.

What changed:
- **Kit:** `TimelineExpected`, and `expectedDash`, now shared by the ring and the timeline.
- **Day screen:** `VerticalTimeline(expected)` draws the plan's first sleep, today only, under the
  "All" filter.
- **Words:** strings in EN and PT.

Screens looked at: `day_expected_block_light`, `day_expected_block_ptBR_dark`,
`day_expected_past_light`, `day_expected_while_napping_light`, `day_today_expected_light`.

## What failed first, and the fix

| Found | Fix |
|---|---|
| The plan said the "Sleep" filter would show it too, but that filter shows a plain list, and a block on a rail inside it would float | "All" only; the docs say so |
| A night-long bedtime bar would push the day down | Bedtime gets a short `space6` bar; its length isn't the point |
| A past window in coral would scold | "Past its window" in `muted` |
