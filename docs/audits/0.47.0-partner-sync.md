# Audit: partner sync (0.47.0)

Date: 2026-11-04 · Auditor: Claude (impeccable, native; graphic-design-fundamentals §13;
less-is-more; and a security review of the protocol)

## Scope

The owner asked for "a Wi-Fi sync between partners". What was added:
- **Code:** `sync/` (merge, crypto, protocol, PartnerSync), the github build's NSD link, and a
  stub link for the play build.
- **Database:** the `deletions` table (Room 4 → 5).
- **Screens:** Settings › Sync and the pairing sheet.
- **Messages:** the "From …" snackbar.

Screens looked at: `sync_settings_light`, `pair_looking_light`, `pair_compare_light`,
`pair_compare_ptBR_dark`, `pair_waiting_light`, `pair_done_light`.

## Security review

| Risk | How it's handled |
|---|---|
| Someone on the same Wi-Fi joins the pairing (man in the middle) | Numeric comparison: the six digits come from the ECDH secret and the whole transcript (both keys, both nonces, both names). A middle party makes the two phones show different numbers. Guessing a match is 1 in a million, once, while both parents watch |
| One parent taps "Same number" by mistake | The other phone must confirm too: each sends a MAC under the new key, and neither keeps the key without the other's |
| A stranger asks to sync | It must answer an HMAC challenge over both phones' fresh nonces with the pair key. It's refused before any data is sent (`SyncProtocolTest`) |
| Someone listens on the Wi-Fi | Each log crosses sealed with AES-256-GCM under a per-session key (HKDF over both nonces); changed bytes fail to open (`SyncCryptoTest`) |
| A replayed session | Fresh nonces on both sides every time; old MACs don't fit |
| The pair key at rest | App-private storage, as the log; `allowBackup="false"`; Unpair forgets it |
| A huge frame from a bad peer | Frames are capped at 64 MB; sockets time out (30 s for a sync, 3 min for pairing) |
| Hand-rolled crypto | Only HKDF (RFC 5869, over the platform's HMAC); everything else is `java.security` |
| The play build | Has no INTERNET permission and no socket; its link is a stub; the permission check is unchanged for both builds |

Open: the pair key isn't wrapped by Android Keystore (P3). It has the same protection as the log
itself, which is in the same private storage.

## What failed first, and the fix

| Found | Fix |
|---|---|
| A deleted entry would come back from the other phone (sync merges; delete wasn't remembered) | The `deletions` table; `EventDao.delete` records it; the merge applies it unless the entry was edited after (Undo) |
| Both phones syncing to each other at once could deadlock (each held its lock while waiting for the other) | The lock covers only writing the merge, never a conversation |
| A refused stranger would wait for a reply forever | A refusal closes the connection (`Wire.close`), so the other side's wait ends |
| "Synced with …" above "Not synced yet" | "Paired with …" |
| Settings › Privacy said "stays on this phone" | When sync is available: "this phone and the phone you paired, on your Wi-Fi" |
| A wrong 4 → 5 migration would crash the app on update | `DeletionsMigrationTest` compares the SQL with Room's exported schema |
